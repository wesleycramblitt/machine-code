Replace the outdated human vs agent review setting on issues. It can be removed entirely with this feature: wire up gh cli to 1.) check a repos merge policy and conclude whether we can directly merge into origin/main or if a PR is required. This check should be periodic on new runs and before merges.  If a PR is created, we should default to creating one and waiting on human review (this would be the new awaiting human review status replacing the old).  2.) When a user completes the PR, we need some way of knowing and changing the status of the issue. A heartbeat using gh cli to check the PR status will suffice (should batch these calls and don't do it too often, wire into existing heartbeat code in a clean way).  3.) If a PR is rejected, we should pass the message and full changes to a new run on the issue, and also update the issue status. We need to be careful and intelligent with how we do this ensuring the run gets all of the information it needs to continue on without having to rediscover everything from the past run. The full PR review needs to be sent obviously.
